## Запуск

Нужны браузер с WebGL и интернет для Three.js r128 (cdnjs). Сервер сборки не требуется.

```bash
python3 -m http.server 8000
```

Открыть `http://localhost:8000`, затем «В БОЙ». Для офлайн-запуска скачайте оригинальный `three.min.js` версии r128, поместите рядом с `index.html` и замените CDN URL в `<script src=...>` на `three.min.js`. Сохраняются относительные пути, поэтому проект рассчитан на GitHub Pages без сборки.

### Пресеты

- `?quality=low`: DPR ≤1, тени 512, 48 частиц.
- `?quality=medium`: DPR ≤1.5, тени 1024, 96 частиц (по умолчанию).
- `?quality=high`: DPR ≤2, тени 2048, 160 частиц.

В DevTools во время боя команда `V.stats()` возвращает FPS (скользящий интервал ~1 с), время последнего кадра, draw calls, треугольники, пиковые показатели, число юнитов, GPU-ресурсы и версию Three.js. Показатели зависят от устройства, сцены и пресета. `V.project(x,z,y)` помогает диагностировать соответствие координат касания.

## Реализовано в коде

- `graphics/art.js` — общие геометрии с фасками, процедурные текстуры, материалы, баннеры, кристаллы, instancing, кеш объединённых моделей, здоровье и освобождение ресурсов.
- `graphics/environment.js` — каменная кладка, стены, золотые рунические линии, центральная печать с прерывистым ободом, вода, два деревянных моста, фонари, кристаллы, лианы, мох, цветы.
- `graphics/towers.js` — две круглые цитадели с ядрами и четыре боковые башни со стражами, анимации, развалины.
- `graphics/characters.js` — восемь классов юнитов, отличимые силуэты, командные цвета, анимации перемещения, атаки, появления и реакции на попадание.
- `render3d.js` — освещение, камера с подгонкой по границам поля и объёму башен, выбор точки через Raycaster, графические пресеты, пул частиц и эффектов, диагностика.
- `index.html`, `style.css` — подключение модулей, оформление и адаптивный интерфейс.
- `game.js` — оригинал, побайтно совпадает с GitHub; баланс, колода, бот, время, награды, локальные сохранения и игровые координаты не изменялись.

### Художественные решения

Сцена полностью процедурная, без 2D-фона, внешних моделей или сборщика. Камера 65° / FOV 26°; сохраняет всю игровую область и объём башен. Крайние декоративные кристаллы/стены могут частично кадрироваться, как в референсе. Центральная печать не является мостом: каменный обод намеренно прерывается, поверхность полупрозрачная. Золото настроено с metalness .35 вместо .65, чтобы сохранить читаемость без HDR environment map. Локальное свечение создаётся emissive-материалами и glow-спрайтами, без тяжёлого постпроцессинга. Финальный вид материалов и освещения нуждается в проверке в реальном WebGL.

## Тестирование

См. `TEST_REPORT.md`.

```bash
# Проверка синтаксиса
node --check render3d.js
for f in graphics/*.js game.js; do node --check "$f"; done
# Аналитическая проверка камеры
python3 tests/check-camera.py
# Регрессия интерфейса / игры (с заглушками V и localStorage)
pip install playwright
python3 -m playwright install chromium
python3 tests/check-logic.py
# Полный WebGL-тест с реальными скриншотами и метриками
python3 tests/check-webgl.py --quality medium
# Если CDN недоступен, используйте локальную копию r128:
python3 tests/check-webgl.py --three /path/to/three.min.js --quality medium
```

Полный тест сохраняет реальные снимки `test-output/arena-*.png`, стресс-сцену, разрушенную башню и `webgl-report.json`. В тестовой среде ChatGPT эта стадия заблокирована, поэтому снимки и метрики не включены и визуальное соответствие не подтверждено. FPS на физическом смартфоне следует измерять отдельно, не сравнивая его напрямую с программным WebGL в headless Chromium.
